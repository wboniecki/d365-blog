# D365 Dev Blog — project context for Claude Code

Personal blog + portfolio of a Dynamics 365 Finance & Operations developer.
Posts are written in Obsidian (Markdown). The look is inspired by the D365 F&O
web client, rebuilt with Microsoft's open Fluent 2 design language — inspired,
never a copy of Microsoft's proprietary UI or branding.

The owner is learning modern web dev through this project. Explain non-obvious
choices briefly, prefer small reviewable steps, and don't add dependencies
without saying why.

## Stack (decided 2026-10-20)

| Layer        | Choice                                                                              |
| ------------ | ----------------------------------------------------------------------------------- |
| Writing      | Obsidian + Obsidian Git plugin                                                      |
| Site         | Astro + TypeScript (strict), fully static output                                    |
| Styling      | Fluent 2 design tokens as CSS custom properties + plain CSS (no Tailwind, no React) |
| Hosting      | Azure Static Web Apps, Free plan                                                    |
| CI/CD        | GitHub Actions (workflow generated by Static Web Apps)                              |
| Phase 2 API  | Rust + Axum on Azure Container Apps (scale to zero), in `/api`                      |
| Phase 2 data | Azure SQL Database free offer                                                       |

Node.js: 22 LTS or newer even-numbered release (Astro requires >= 22.22.0).
Package manager: npm.

Note: the Static Web Apps Free plan can't proxy `/api` to Container Apps
(Standard plan only). Phase 2 API runs on its own subdomain with CORS.

## Dev environment

Host is Bazzite-DX (immutable Fedora Atomic) — never install dev tools on the
host. All tooling runs in distrobox containers defined in `distrobox.ini`:

- `d365-blog-web`: Ubuntu 24.04 toolbox, Node 22 LTS (NodeSource), git, gh, az
- `d365-blog-rust`: phase 4, separate home for cargo/rustup

Claude Code runs inside the box (`distrobox enter d365-blog-web`, then `claude`),
started from `/var/home/boniek/dev/projects/d365-blog` — inside the box `~` is
`/home/...`, which Claude Code treats as a different project (separate sessions
and memory). VS Code is installed in the same box and exported to the host menu;
use a "D365 Blog" VS Code profile, never the host's own VS Code (both share
`~/.config/Code`). Recommended extensions are in `.vscode/extensions.json`.
Phase 4 adds: rust-analyzer, Even Better TOML, CodeLLDB, Container Tools, Azure
Container Apps, SQL Server (mssql). If a tool is missing, add it to
`distrobox.ini` rather than installing ad hoc, so the box stays reproducible.
The dev server must listen on localhost (`npm run dev` → http://localhost:4321),
which the host browser can reach.

## Content

- Posts live in `src/content/posts/` as `.md` files — this folder is the
  Obsidian vault (or a folder inside it).
- Frontmatter: `title`, `description`, `date` (YYYY-MM-DD), `tags` (list),
  `module` (e.g. "X++", "Data entities", "Integrations", "DevOps"), `draft` (bool).
- Must render Obsidian syntax: `[[wikilinks]]`, `![[image.png]]` embeds,
  callouts (`> [!note]`, `> [!warning]`) as Fluent-style message bars.
- Code highlighting must support X++ (fall back to C#-like grammar if no X++ grammar exists).
- Validate frontmatter with an Astro content collection schema (zod).

## Design (from the canvas prototype)

Layout metaphors from D365 F&O:

- Dark navy top navbar (site name, search, RSS/GitHub icons)
- Left navigation pane: Workspaces (Home, All posts, Portfolio, Snippets, About)
  and Modules (post categories with counts); collapses on mobile
- Action pane under the navbar (Filter, Sort, Subscribe / Copy link, View source)
- Home = "workspace": summary tiles (latest post, counts), recent posts as a
  data grid (Title, Module, Published, Read time), right-side FactBoxes (About, Tags)
- Post page: article card, code blocks with filename header, right-side
  "On this page" TOC and Related FactBoxes

Starting tokens:

- Navbar `#0C2340`, accent `#0F6CBD`, accent-dark `#0C3B5E`, accent-tint `#EBF3FC`
- Page `#F3F2F1`, surface `#FFFFFF`, border `#E1DFDD`, row-divider `#EDEBE9`
- Text `#242424`, text-secondary `#484644`, text-muted `#605E5C`
- Warning bar bg `#FFF4CE`, border `#F2E1A0`, icon `#8A6100`
- Fonts: "Segoe UI", Inter, system-ui (body); JetBrains Mono (code)
- Square-ish corners (0–4px), 1px borders, no shadows/gradients
- Must be responsive, accessible (WCAG AA contrast, real buttons/links, 44px touch targets)
  and support dark mode later.

## Phase 2 decisions (2026-10-22)

These override the sections above where they differ.

- Audience: portfolio + knowledge base for D365 developers. English only.
- Vault: `src/content/posts/` is opened as its own Obsidian vault. It holds only public posts.
- Images: one shared `src/content/posts/_attachments/` folder (set as Obsidian's
  default attachment location), so Astro can optimize them.
- URLs: the filename is the slug, in kebab-case → `/posts/<slug>/`. `[[slug]]` resolves by filename.
- Fonts: Inter and JetBrains Mono are self-hosted via `@fontsource-variable/*`
  (no Google Fonts requests). Segoe UI is used only where it is installed.
- Dark mode: not before Phase 3.
- Workspaces: Home, All posts, About. Portfolio and Snippets are dropped for now.
- Wikilinks to a missing or draft post fail the production build and warn in dev.
- Search, Filter, Sort and Subscribe are real `<button>`s that do nothing yet.
- `module` is a zod enum: "X++", "Data entities", "Integrations", "DevOps".
- `tags` must match `^[a-z0-9-]+$`.
- X++ code blocks: Shiki aliases `xpp`/`x++` to `csharp`. A custom grammar may come later.
- Obsidian syntax uses small remark plugins of our own in `src/lib/`, with no dependencies.
- Workflow: one feature branch and PR per step. SWA builds a preview URL for each PR. `main` is production.
